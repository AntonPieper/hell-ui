# Time Picker redesign: interaction spec

- Status: Accepted (#360) and implemented (#361)
- Date: 2026-07-27
- Scope: the `hell-ui/time-picker` Composite panel and its documented
  composition with `hell-ui/time-input`, Field, Control Group, and Popover.
- Evidence sources: current `packages/angular/time-picker/time-picker.ts`,
  `packages/angular/time-input/time-input.ts`, the docs pages and examples
  under `apps/docs/src/app/pages/components/{time-picker,time-input}`, the
  prior-art survey below, and the ADRs referenced inline.

## Problem

The current `hell-time-picker` renders one `role="spinbutton"` value per unit
with a small `−`/`+` button pair and a fixed `00/15/30/45` minute-preset grid.
Three concrete failures motivated #360:

- **Desktop**: the spinbuttons are keyboard-operable but visually cryptic —
  the affordance is two tiny step buttons, and reaching `:37` from `:00` takes
  either 37 clicks or knowledge of the hidden PageUp contract. Nothing shows
  the range of choices.
- **Touch**: repeated small-target tapping is the whole interaction. There is
  no scrolling, no large targets, and the `−`/`+` buttons sit at the size
  Hell reserves for dense desktop chrome.
- **Visual**: the mixed readout / spinbutton row / preset-pill grid reads as
  three unrelated widgets, not one picker, and the fixed minute presets are a
  bundled preset of exactly the kind the Customization Surface guidance warns
  about (`docs/adr/mode-inputs.md`).

What already works and must be preserved:

- The two-surface split. `input[hellTimeInput]` is the Typed Value Input
  (keyboard-first text entry, parsing, drafts, forms) and `hell-time-picker`
  is a forms-free visual selection panel. `docs/adr/projection-first-interactions.md`
  pins this: "Typed Value Input behavior lives on real inputs; pickers,
  steppers, and adornments compose separately."
- The picker's `value` model as its only writable committed state. Per
  `docs/adr/0001-control-value-authority.md` the picker keeps a model input
  and gains no Angular forms contract; `HellTimeInput`'s `value` model is the
  Control Value Authority when the two compose.
- The explicit composition recipe (Control Group + Popover + consumer-owned
  trigger, Done action, and focus policy) — neither entry point hides the
  other.

## Prior art survey

Six mature systems plus the platform baseline were compared hands-on against
their public docs (July 2026).

| System | Model | Strengths | Weaknesses for Hell |
| --- | --- | --- | --- |
| **Angular Material `mat-timepicker`** (material.angular.dev) | Text input + toggle + dropdown implementing the ARIA combobox pattern; the popup is one flat `role="listbox"` of complete times generated by `interval` or an `options` list. Typed input is parsed; `min`/`max` validate. | Simple, proven a11y story; typing stays primary; interval list is great for appointment-style times. | A flat list of whole times cannot express arbitrary precision (`14:37`, seconds) without hundreds of options. Hell already owns the typing half in Time Input, and a "list of complete times" is a Select/Combobox recipe, not a picker panel. |
| **Material Design 3 time pickers** (m3.material.io; material-components-android) | Two modes: a clock **dial** with a draggable handle, and an **input** mode (keyboard) reachable from the dial via an icon toggle. | Excellent finger ergonomics on phones; strong brand identity. | The dial is pointer-geometry-heavy, weak for keyboard and screen readers (both platforms fall back to input mode), expensive to build, and visually foreign to a dense business system. The two-mode toggle is exactly the bundled mode switch `mode-inputs.md` rejects. |
| **React Aria / Spectrum `TimeField`** (react-aria.adobe.com) | No panel at all: a group of individually focusable **segments** (hour, minute, dayPeriod), each a spinbutton-like unit edited by arrows or typed digits with auto-advance; works with touch screen readers. | The best keyboard entry model in the survey; locale-driven; no parsing ambiguity because each segment is bounded. | It is a field, not a picker — Adobe ships no time panel. Hell's Time Input already covers keyboard entry with one native input (native form submission, autofill, one draft model); replacing it with segments would rebuild the Typed Value Input contract for marginal gain. |
| **Ant Design `TimePicker`** (ant.design) | Input + panel of **scrollable unit columns** (hour / minute / second), one column per format unit; tap or click selects; `changeOnScroll` and `needConfirm` govern commit timing. | The de-facto standard panel for arbitrary-precision times; columns scale from `HH:mm` to `HH:mm:ss` by adding a column; good touch targets; scroll + tap both work. | Commit-on-scroll is accident-prone (Ant makes it opt-in); Ant's a11y story for the columns is weak (generic listboxes with thin labelling) so Hell must do better, not copy. |
| **Fluent UI v9 `TimePicker`** (react.fluentui.dev, compat) | A compat component built on Combobox: freeform text plus a dropdown of increment-generated times. | Cheap to build on an existing primitive; freeform typing. | Same flat-list precision ceiling as Material; shipped as "compat" rather than a first-class pattern, and its freeform parsing has open defects (microsoft/fluentui#30374). Confirms "combobox of times" is a recipe over Select/Combobox, not a picker design. |
| **Carbon `TimePicker`** (carbondesignsystem.com) | Plain text input (`hh:mm`) + sibling `TimePickerSelect` for AM/PM (and timezone). No panel. | Honest minimalism; forms-first. | It is Hell's Time Input + Control Group recipe restated. Offers nothing for the visual-selection panel this ticket redesigns. |
| **Native `input[type=time]`** (MDN) | Platform-owned control: desktop browsers render segmented fields with an optional dropdown; iOS renders wheels, Android a Material dial. Value is always 24-hour `HH:mm[:ss]`; `step` reveals seconds; `min`>`max` wraps midnight. | Zero-JS baseline, ideal mobile keyboards, free locale handling. | Unstylable panel, inconsistent desktop UI across browsers, no design-system identity. Hell has no native/styled time pair today; adding one is a separate `docs/adr/native-styled-control-pairs.md` decision, out of scope here (recorded under Deferred). |
| **shadcn ecosystem / Ark UI** | shadcn ships no official time picker; the community converges on either wrapped native inputs or scroll-column panels (openstatus, shadcn-datetime-picker). Ark UI built a column-based `TimePicker` and then **removed it as experimental** before it reached the public API. | Confirms the column panel as the community endpoint. | Ark's removal is a warning: the column panel is easy to demo and hard to finish (a11y, bounds, steps). The spec below front-loads those hard parts. |

### What Hell adopts, and why

- **Adopted from Ant / iOS / community consensus**: the panel becomes
  **scrollable unit columns** — one column per visible unit. This is the only
  surveyed model that is simultaneously touch-friendly (scroll + large tap
  targets), precision-complete (any minute/second, unlike interval lists), and
  visually one widget.
- **Adopted from React Aria**: per-unit keyboard editing with typed-digit
  entry and auto-advance — applied to the columns, not to a new segment field.
  Arrow/Home/End/PageUp/PageDown vocabulary carries over from the current
  spinbuttons unchanged.
- **Adopted from Ant's `needConfirm` analysis**: selection commits on
  activation, never on scroll. Scrolling reveals; tapping/arrowing selects.
  A confirm-to-commit step stays consumer-owned (the Done button recipe).
- **Adopted from Material (Angular)**: `min`/`max` bounds on the panel that
  match the input's same-day bound semantics, and the input-plus-toggle field
  anatomy as the canonical composition recipe.
- **Rejected**: the M3 dial (pointer-geometry cost, weak keyboard/AT story,
  wrong register for dense business UI); the flat combobox-of-times as the
  picker's identity (precision ceiling; it is already expressible today as a
  Select/Combobox recipe and needs no entry point); replacing Time Input with
  a segmented field (rebuilds the Typed Value Input contract Hell just
  finished, per ADR 0001); commit-on-scroll (accidental commits); a
  dial/input or wheel/list mode switch (`mode-inputs.md`).

## Redesigned interaction

### Anatomy

`hell-time-picker` stays an owned-anatomy Composite (element selector, camelCase
Public Parts, `data-slot` markers). New anatomy, top to bottom:

```
root
├── header
│   └── readout            formatted committed value, or placeholder
└── columns                one horizontal row of unit columns
    └── column (×2–3)      data-unit="hour" | "minute" | "second"
        ├── columnLabel    "Hours" / "Minutes" / "Seconds" (Label Contract)
        └── options        the scrollable option list
            └── option     one selectable unit value, data-slot="option"
```

Removed anatomy: the whole unit/preset structure — the authoritative removed
Public Part list lives under "Public API for #361" below. The `−`/`+`
steppers disappear (columns make the value range directly visible and
tappable) and the fixed minute-preset grid disappears (it bundled one team's
presets; granularity is now the `minuteStep` input, and bespoke preset rows
are consumer markup beside the picker).

The seconds column renders only when `seconds` is set, exactly as today.

### Value semantics

- `value` stays `model<HellTimeValue | null>` — one committed structured
  value, no forms contract (ADR 0001 applicability table).
- **Null renders as no selection.** The readout shows a placeholder
  (`--:--` / `--:--:--`) instead of today's silent midnight, and no option is
  selected. The first activation in any column commits a complete
  `HellTimeValue` in one write — preserving today's "first user step commits
  a structured value" contract without ever displaying a fake 00:00.
  **First-commit rule:** the committed value is the *earliest in-range* time
  whose activated unit equals the chosen option (untouched units take the
  smallest values that keep the whole value within `min`/`max`; with no
  bounds this reduces to defaulting untouched units to `0`). This is
  definitionally consistent with option disabling below: an option is enabled
  exactly when at least one in-range value contains it, so the earliest such
  value always exists — e.g. with `min` 09:00 and a null value, activating
  minute `30` commits `{hour: 9, minute: 30, second: 0}`, never an
  out-of-range `{hour: 0, minute: 30}`.
- Every activation commits immediately through the model (one `valueChange`
  per user action). No internal draft, no confirm state.
- New `min` / `max` inputs (`HellTimeValue`, unset by default) mirror
  `hellTimeInput`'s inclusive same-day bounds. Options that cannot participate
  in any in-range value are disabled (`data-disabled`, `aria-disabled`),
  skipped by keyboard traversal, and inert to pointer activation. No
  midnight-wrapping ranges (the native input's periodic domain is explicitly
  not adopted; Time Input has no wrap either).
- New `minuteStep` / `secondStep` inputs (default `1`; must be a positive
  integer that divides 60) control column granularity. An invalid step value
  throws in dev mode (`ngDevMode`) and falls back to `1` in production
  builds. When the committed value does not sit on the step grid (external
  write, typed value from the composed input), the column renders that value
  as one extra in-place option so the selection is always visible — adopted
  from Material's typed-value behavior. Picker-internal interaction never
  creates off-step options; only external/committed values do.
- Hour cycle stays 24-hour (`00`–`23`). See Deferred for `h12`.

### Desktop keyboard flow

One Interaction State Machine per column; no second model behind it.

- **Tab / Shift+Tab** move between columns. Each column is one tab stop:
  roving `tabindex` keeps exactly one focusable option per column — the
  selected option, else the first enabled option.
- **ArrowUp / ArrowDown** move option focus within the column, skipping
  disabled options, without wrapping (today's no-wrap contract stays).
  **Selection follows focus**: the focused option becomes the committed unit
  value. This matches the surveyed listbox convention and today's
  arrow-steps-commit spinbutton behavior.
- **ArrowLeft / ArrowRight** move focus to the previous / next column
  (React Aria segment convention). This replaces their current duplicate
  decrement/increment role — Up/Down own value movement.
- **Home / End** jump to the first / last enabled option. **PageUp /
  PageDown** move by five options, preserving today's large-step contract.
- **Typed digits** edit the focused column React Aria-style through a
  two-digit accumulator defined against the unit's numeric domain (0–23 or
  0–59), not against the rendered option set. Digits accumulate into a unit
  value (`3`, then `7` → `37`); the buffer **completes** when a second digit
  arrives or when appending any further digit would exceed the unit maximum
  (hours: `7` completes immediately because `70` > 23; `2` waits for a
  second digit). On completion the buffered value **snaps to the nearest
  enabled option** — ties resolve to the earlier value, disabled options
  never match — the snapped option is selected and committed, and focus
  auto-advances to the next column. With `minuteStep` 15, typing `3`, `7`
  therefore selects `30` (nearest of `30`/`45`); typing never creates an
  off-step option (see Value semantics). The accumulator resets on column
  change or after a short timeout.
- Enter/Space perform no picker-level action (selection already followed
  focus); inside the Popover recipe, Escape closes and restores the trigger
  via the delegated dismissal engine, untouched by this spec.

The full keyboard entry story for a field remains: type in the Time Input.
The panel's keyboard contract exists so the picker is operable without a
pointer, not to replace typed entry.

### Touch flow

- Columns scroll natively (`overflow-y: auto`, momentum) with CSS scroll-snap
  aligning options; a **tap selects** — scrolling never commits.
- The selected option auto-centers in its column on open and on external
  value changes. This measurement/scroll coordination is the difficult
  runtime work that justifies the Composite owning this DOM (CONTEXT.md,
  Composite).
- Option hit targets: the recipe sizes options at the control-height token on
  fine pointers, and component CSS raises them to a ≥44px minimum under
  `@media (pointer: coarse)` — structural, non-recipe CSS per
  `docs/adr/part-style-map.md` (cross-part/structural rules may live in
  component CSS scoped by `data-slot`).
- Fixed column height (about seven visible options) with subtle top/bottom
  fade masks signalling scrollability.

### Accessibility semantics

- Each `options` list is `role="listbox"` labelled by its `columnLabel` via
  `aria-labelledby` (Label Contract strings: `hours`, `minutes`, `seconds`).
- Each `option` is `role="option"` with `aria-selected`, `data-selected`,
  and `aria-disabled`/`data-disabled` when out of bounds. The option's
  accessible name is its padded text (`"05"`); the labelled listbox provides
  the unit context.
- Selection follows focus, so assistive tech announces "05, selected,
  Minutes" naturally on arrow movement — no live region (a live region would
  double-announce every arrow step).
- The root **gains** `role="group"` and an accessible name from
  `selectedTime`/`noTimeSelected` — today's host has neither a role nor a
  name (the `selectedTime` label currently sits on the readout span as
  `aria-label`). That name lives on the root **only**: the `readout` becomes
  presentational (`aria-hidden="true"`, not focusable) so the current value
  is exposed exactly once and cannot double-announce against the group name.
- The root keeps `data-slot="root"` and today's
  `data-disabled`/`aria-disabled` reflection; `disabled` removes all options
  from the tab order.
- Disabled-option traversal matches the repo keyboard matrix
  (`docs/architecture/keyboard-navigation-matrix.md`): disabled options are
  skipped by arrows and typeahead and cannot be selected.
- **Delegate-first check (required in #361)**: per the decision rule in
  `docs/architecture/manual-runtime-ownership.md`, evaluate ng-primitives
  listbox (and Angular Aria listbox) as the column engine before writing
  roving-focus code. Delegation is acceptable only if it preserves this
  contract (selection-follows-focus, no-wrap, disabled skipping, roving
  tab stop) and syncs through the picker's `value` model per
  `docs/adr/ng-primitives-state-adapter.md`. If no delegate fits, the column
  keyboard code is Hell-owned, small, and unit-tested — the menu-typeahead
  precedent — and the ownership matrix gains a row saying so.

### Composition with field and control patterns

- The **canonical field recipe** (promoted to both docs pages) stays the
  explicit composition the Time Input docs already demonstrate: `hellField` +
  `hellControlGroup` wrapping an `input[hellTimeInput]` and a
  `hellControlGroupAction` toggle button (`aria-label` "Choose time") that is
  a `hellPopoverTrigger` for a panel containing `hell-time-picker` and a
  consumer-owned Done button.
- Ownership in the recipe is unchanged: the input's `value` model is the
  Control Value Authority; the picker reads `[value]` and writes back through
  `(valueChange)`; the consumer owns trigger, shared value, close action, and
  focus policy (Done → focus returns to the input; Escape → the popover
  engine restores the trigger). The picker itself still ships **no** trigger,
  popover, field, or forms API — Material's input-toggle-panel anatomy is
  achieved by composition, not by widening the entry point.
- Standalone inline use (the picker directly in a workflow panel) remains
  first-class; nothing in the redesign assumes a popover.
- `seconds`, `min`, `max` should be bound to the same values on both the
  input and the picker when composed; the docs recipe shows this once.

## Public API for #361

```ts
// hell-ui/time-picker
export class HellTimePicker {
  value: ModelSignal<HellTimeValue | null>;        // unchanged
  seconds: InputSignal<boolean>;                   // unchanged, default false
  disabled: InputSignal<boolean>;                  // unchanged, default false
  min: InputSignal<HellTimeValue | undefined>;     // new, same-day inclusive
  max: InputSignal<HellTimeValue | undefined>;     // new, same-day inclusive
  minuteStep: InputSignal<number>;                 // new, default 1, divides 60
  secondStep: InputSignal<number>;                 // new, default 1, divides 60
  ui: InputSignal<HellUiInput<HellTimePickerPart>>;
}

export type HellTimePickerPart =
  | 'root' | 'header' | 'readout'
  | 'columns' | 'column' | 'columnLabel' | 'options' | 'option';

export interface HellTimePickerLabels {
  hours: string;
  minutes: string;
  seconds: string;
  selectedTime: (time: string) => string;   // unchanged
  noTimeSelected: string;                   // new — root group name when null
}
```

Removed from the public surface (authoritative list against the current
`HellTimePickerPart` union in `packages/angular/time-picker/time-picker.ts`):

- **Parts (8 removed, 5 added):** `units`, `unit`, `unitLabel`,
  `unitControl`, `unitValue`, `unitStep`, `minutePresets`, and
  `minutePreset` are removed; `columns`, `column`, `columnLabel`, `options`,
  and `option` are added; `root`, `header`, and `readout` carry over.
- **Label fields (4 removed, 1 added):** `decreaseUnit`, `increaseUnit`,
  `minutePresets`, and `minutePreset` are removed; `noTimeSelected` is
  added; `hours`, `minutes`, `seconds`, and `selectedTime` carry over.

`HellTimeValue` re-export, entry point path, selector,
`hell-entrypoint.json` category (`composite`), and the
recipe-module/stylesheet wiring rules (`docs/adr/part-style-map.md`) are
unchanged.

## Breaking changes and release notes (#361)

This spec document itself is No Consumer Change (documentation only — no
Change Fragment). Implementation in #361 is one Breaking Consumer Change for
`hell-ui/time-picker` and records one Breaking Change Fragment covering: the
part union change (Part Style Maps targeting removed parts), the label
interface change, the new `min`/`max`/`minuteStep`/`secondStep` inputs, the
null-renders-as-placeholder behavior change, and migration guidance (preset
grids become consumer markup; step-button `ui` refinements map to `option`).
`hell-ui/time-input` has no API change; its docs example updates are not a
Consumer Change.

  invalid-step throw), selection-follows-focus, no-wrap arrows,
  Home/End/PageUp/PageDown, digit entry with buffer completion,
  snap-to-nearest-enabled-option, and auto-advance, disabled-option skipping,
  bounds disabling, the bounds-aware null first-commit rule, off-step value

## Deferred (explicit non-goals)

- **12-hour display (`h12` day-period column).** `HellTimeValue` stays
  canonical 24-hour and the panel renders `00`–`23`; the Time Input adapter
  already parses `am`/`pm` text. A locale-driven hour-cycle needs its own
  design (label contract, column order, parsing symmetry) and must not block
  the panel redesign.
- **Native/styled time pair** (`input[type=time][hellNativeTimeInput]`). A
  platform-owned flavor is attractive for forms-first mobile surfaces but is
  a `native-styled-control-pairs.md` product decision, not part of this
  redesign.
- **Confirm-to-commit picker mode.** Stays a consumer recipe (Done button);
  adding a `needConfirm`-style input would introduce a second commit model.
- **Duration / range picking.** Out of the fixed-clock domain, unchanged.
