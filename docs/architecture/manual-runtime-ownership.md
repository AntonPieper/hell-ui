# Manual runtime ownership matrix

- Date: 2026-05-29
- Updated: 2026-07-29
- Scope: custom Hell browser/runtime behavior that should be kept, deleted from
  core, or delegated before a production-ready claim.

## Decision Rule

Prefer Angular CDK/A11y, Angular Aria, ng-primitives, or dedicated feature
packages when they own focus, keyboard, overlay, grid, worker, or browser
runtime risk better than Hell. Keep Hell-owned runtime only when it is a small,
documented public contract with tests.

Allowed direct browser-global seams follow
`docs/architecture/browser-global-seams.md` and are enforced by ESLint
`no-restricted-globals` with justified inline disables.

| combobox resting-pointer guard | `packages/angular/combobox/combobox.ts` (`HELL_COMBOBOX_POINTER_BOUNDARY_EVENTS`, `HELL_COMBOBOX_POINTER_USE_EVENTS`, `ignorePointerAtRest`); `packages/angular/combobox/combobox.spec.ts`; `e2e/menu-select-combobox-keyboard.spec.ts` | **Keep narrowly; this seam does write upstream and is the heaviest Hell-owned runtime in `combobox.ts`.** On a freshly attached dropdown, a capture listener calls `stopImmediatePropagation()` on eight boundary event types (`pointerenter`/`leave`/`over`/`out` plus the four legacy `mouse` names `ngpInteractions` also listens to) so they never reach the delegated option engine, and the first `pointermove`/`pointerdown`/`mousemove`/`mousedown` lifts the guard and **synthesizes a `pointerenter` into that engine**, carrying the originating event's `pointerType`. Hell owns this because ng-primitives treats every boundary event as intentional: a panel placed asynchronously moves options under a pointer the user never touched, and the engine answers by reassigning or clearing the active option. **Delegate and delete the whole seam when ng-primitives filters non-intentional boundary events itself** — a hover/activation model that ignores boundary events not preceded by pointer movement, or an input to disable pointer-driven activation. Do not broaden it into a general pointer-intent layer, and do not extend it to other primitives by copying; `NgpSelect` has the same latent defect and needs its own decision. | Recheck `ngpInteractions` (`fesm2022/ng-primitives-interactions.mjs`, `onHoverBegin`/`onHoverFinished`) and the combobox option primitive on every ng-primitives upgrade — in 0.123.0 hover already ignores `pointerType === 'touch'` on both edges, which is why the replay must carry the real pointer type. CDK A11y `ActiveDescendantKeyManager` is not an alternative here: it has no pointer-intent concept either. The synthesized `pointerenter` is Hell writing into a delegated engine's input: a changed upstream hover contract turns it into a phantom hover or a wrong active option. The lift is one-shot per dropdown, so it cannot re-arm if a panel repositions a second time. Both halves depend on browser event ordering that jsdom cannot express — if any engine synthesizes a `pointermove` after a layout-driven hover recompute (Blink's fake-mouse-move path), the guard lifts and the defect returns unnoticed. | Unit coverage for the resting-pointer active-option guard, no phantom hover, the lift-and-replay on real pointer use, and the touch replay's pointer type — each mutation-verified. Browser coverage on all three engines is mandatory, not optional, because the contract is event ordering: a moved pointer takes the active option and paints `data-hover`, and a dropdown painted under a parked pointer leaves the keyboard's active option and hover untouched, with the resting point asserted to actually sit over a non-active option. |

## Delegate-first check: time picker columns vs `NgpListbox` (2026-07-27)

Required by `docs/architecture/time-picker-redesign.md` before writing any
Hell-owned roving-focus code for #361. Evidence is the installed
`ng-primitives@0.123.0` package: `types/ng-primitives-listbox.d.ts` and
`fesm2022/ng-primitives-listbox.mjs`.

| Contract the spec requires | `NgpListbox@0.123.0` | Verdict |
| --- | --- | --- |
| Roving `tabindex`; one focusable option per column | `ActiveDescendantKeyManager` (`.mjs` line 281). DOM focus stays on the listbox host and `aria-activedescendant` names the active option. | **Mismatch** — a different focus model, not a configurable option. |
| Selection follows focus | `onKeydown` moves the active item only; selection happens on `Enter`/`Space`. | **Mismatch** |
| Typed digits drive a two-digit numeric accumulator with snap-to-nearest and auto-advance | `ngAfterContentInit` hard-wires `.withTypeAhead()` (`.mjs` line 298), a string-prefix label matcher that swallows printable keys. There is no input to disable it. | **Conflict** — it would consume the digits before Hell sees them. |
| Commit through the picker's own `value` model | `value` is `InputSignal<T[]>`; `selectOption`, `activateOption`, and `isSelected` are all marked `@internal`. | **Mismatch** — no public single-value selection API. |
| No wrap at column bounds | No `.withWrap()`; the CDK default does not wrap. | Match |
| Disabled options skipped | CDK `ListKeyManager` skips disabled items. | Match |
| Home/End | `.withHomeAndEnd()` | Match |
| PageUp/PageDown by five options | `withPageUpDown()` is not enabled. | Missing |
| ArrowLeft/Right move between columns | `.withVerticalOrientation()` only; horizontal keys are unhandled. | Neutral — layerable |

Three of the four mismatches are structural rather than missing options, and
the typeahead conflict cannot be switched off through the public API, so
delegation would mean fighting the primitive on its own keydown path. Angular
Aria is not an installed dependency, and taking on a new public peer for one
column engine is a larger decision than this ticket. The decision is therefore
Hell-owned, following the menu-typeahead precedent: the logic is pure, lives in
one module, and is covered by unit and browser tests.

## Review Usage

Architecture reviewers should start from this matrix before flagging manual
runtime as a blocker. A finding must name the matrix row and explain whether
the row's decision is wrong, untested, or missing a narrow follow-up.
